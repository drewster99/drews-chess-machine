## Analysis (analyzer, full)

G5 analysis (GUI save consistent cut): app#1 REAL (mostly), app#8 REAL but minor; plus one NEW HIGH bug found next to app#8 (Promote Trainee Now never folds the fed counts).

GROUP SUMMARY
- GUI session saves and promotion saves capture trainer state while training is paused, but read the sampler, the game serial, the fed counts and the arena count after the gates resume. So a resume can report EXACT for rng_sampler/serials when it isn't. The nextGameSerial is always off by at least K, because K new games start the moment self-play resumes. The "promotion doesn't rewind sampler/dropout stream" part is NOT a defect.
- app#8's race window is microseconds. The real cum_games bug is in ManualPromote: it calls resetGameStats() with no fold or rebaseline. On a resumed run this makes the segment's game count negative, so every lineage save fails until enough new games come in. On a fresh run it silently undercounts cum_games.

1. app#1: PARTLY REAL (stream/serial/fed reads: REAL, medium; the "promotion doesn't rewind" part: NOT REAL)
Evidence:
- SessionController+Checkpoint.swift:380-399: self-play is paused only for the champion export, then `selfPlayGate.resume()` at :399. Training is paused at :409 and resumed at :429 after `exportResumeSnapshot()`. Then :446-449 calls `lineageRecordForSave(... dropoutStreamState: try await trainer.dropoutStreamState())`, which reads everything live:

- Serials: BatchedSelfPlayDriver.swift:266-284 drops in-flight games at the pause, and on resume :287-300 immediately builds targetK new games, each calling `nextGameRandom()` and taking a serial. Self-play runs through the whole training-pause wait and trainer export, so the saved nextSerial is always at least cut+K.

The saved buffer therefore holds games whose serials are at or above the saved nextSerial. Once serials are read at the cut, a resume would replay those serials and put duplicate games in the buffer. So the buffer write must also come from the cut.
- Promotion path (Arena.swift): both gates are paused at :379-380 and resumed at :452-453. Then the fold/reset/rebaseline runs at :546-548, `championLineage` at :556-559 and `promotionLineage` at :644-647, all after the resume, and each reads the sampler, serials and fed counts live.
- dropout stream: NOT REAL as a staleness bug. `dropoutStream` only advances in `runDropoutSeedOnQueue` (ChessTrainer.swift:5907-5913), which runs at init (:2261), on network reset (:2487) and in `beginDropoutStream` (:5986). It does not advance per step (the per-step mask state is the Philox state, which is captured under the pause). A late read returns the same value.
- "Promotion doesn't rewind sampler/dropout stream": NOT a defect. The uninterrupted run keeps its post-arena sampler and stream after promotion too (only weights, velocity, clock and Philox are rewound, :388-418). The right value to save is the state at the promotion pause, not a rewound one. Only the late read is wrong.
- Effect: `guiResumeGaps` (Lineage.swift:172-174) adds rngSampler/serials gaps only when the streams are missing. So a resume of such a save logs EXACT for both, but continues from a state the original run never passed through.

- saveSessionInternal (Checkpoint.swift:376-500): take one cut with both gates held.
  ```

  export champion            (error → selfPlayGate.resume(); return)

  trainerExport = exportResumeSnapshot()

  if bufferForSave == nil { selfPlayGate.resume() }

  if bufferForSave != nil { selfPlayGate.resume() }   // on every exit path after the write
  ```
  - Use a small local `releaseSelfPlayIfHeld()` so each error return resumes exactly the gates it holds.
  - Holding self-play through the buffer write costs almost nothing. `write` already holds the buffer lock for the whole multi-GB write, so the driver's next flush blocks on it anyway (and today that block sits on a cooperative thread, see G10 cli#3). Parked on the gate, it sleeps instead.

Today :556 and :644 build the same record twice with different dates.

2. app#8: REAL but LOW as written; it hides a HIGH sibling
Evidence:
- Arena.swift:546-548: `foldLineageFedCounts()` (snapshot under the box lock, Lineage.swift:211-219), then `parallelWorkerStatsBox?.resetGameStats()` (separate lock, ParallelWorkerStatsBox.swift:297-312), then `rebaselineLineageFedCounts()` (third lock). All run after the gates resume at :452-453, while the driver's `recordEmittedGame` (:440-444) runs on other threads. Games emitted between the fold snapshot and the reset, or between the reset and the rebaseline, are lost from cum_games. The window is microseconds per promotion: LOW.
- NEW (HIGH), same mechanism: SessionController+ManualPromote.swift:186 calls `parallelWorkerStatsBox?.resetGameStats()` with NO fold and NO rebaseline.
  - Resumed run: the box is seeded with `emittedGames: rs.emittedGames` (Training.swift:473-488), and `beginLineageSegment` sets the baseline to that count (Lineage.swift:130-131).
  - After Promote Trainee Now, `games = carry + (current − baseline)` is negative, so `LineageTracker.record` throws `negativeSegmentCount` (LineageTracker.swift:228). That kills:
    - the promote autosave itself ("Save failed (lineage)");
    - every periodic and manual session save;
    - Save Champion's segment record;
    - results.json lineage;
    - the next Continue's [RUN] line (`beginLineageSegment` → `lineageRecordForSave`, Lineage.swift:134-138).
    This lasts until the post-reset emitted count catches up to the seeded baseline. The Stop fold (Training.swift:2766) then banks a negative carry, so the undercount becomes permanent.
  - Fresh run (baseline 0): no error, but every game fed before the manual promote silently drops out of cum_games, a measured total that is now wrong.
  - (Adjacent, for G4/G7: ManualPromote also never updates `championOrigin`, unlike Arena.swift:571-574.)

Fix:
- ParallelWorkerStatsBox: add `func resetGameStatsReturningEmittedCounts() -> (games: Int, positions: Int)`. It reads `_emittedGames`/`_emittedPositions` and performs the reset in ONE `lock.withLock`. Make `resetGameStats()` private or delete it so nobody can reset without banking.
- SessionController+Lineage.swift: add one helper and use it in BOTH promotion paths (Arena.swift:546-548 moved inside the paused block per item 1, and ManualPromote.swift:186):
  ```swift
  /// Reset the self-play game stats for a new champion, banking what the
  /// lineage segment counted on the box in the same lock acquisition.
  func resetSelfPlayGameStatsForNewChampion() {
      guard let box = parallelWorkerStatsBox else { return }
      let emitted = box.resetGameStatsReturningEmittedCounts()
      guard let baselineGames = lineageFedCarry.baselineGames,
            let baselinePositions = lineageFedCarry.baselinePositions else { return }
      lineageFedCarry.games += emitted.games - baselineGames
      lineageFedCarry.positions += emitted.positions - baselinePositions
      lineageFedCarry.baselineGames = 0
      lineageFedCarry.baselinePositions = 0
  }
  ```
  - A nil baseline means no segment is counting on this box, so leaving the carry untouched is correct, not a fallback.
  - This is race-free whether or not the gates are held.
  - For ManualPromote, call it before `selfPlayGate.resume()` at :138 so it also lines up with that save's cut.
