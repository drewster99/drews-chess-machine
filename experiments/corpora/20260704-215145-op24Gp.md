## Importer version: why `7452e30` alone won't rebuild it

- The Elite export mixes LF and CRLF months. The CRLF months are roughly 2023-02 to 2024-02, and they also use a different tag set.
- Before commit `18dc34f` ("Fix PGN importer silently dropping games in CRLF files", 2026-07-04 17:13 CDT), CRLF games merged together and were silently dropped.
- Four earlier imports of this same file that day stopped at `imported=10850514 skipped=3707`. Those are the logs `dcm_log_20260704-134351`, `-140526`, `-161901` and `-155807`.
- The 16:51 import produced 14,619,153 games, so the binary already had the fix. That was 22 minutes before the fix was committed, while the recorded HEAD was still `7452e30`.
- The commit's diff over `7452e30` touches only the importer and its test. **Use `18dc34f`.**
- An exact match with build 2016's working tree can't be proven: `corpus.json` doesn't record the dirty flag. The shard body hashes below settle it.

## Rebuild

1. **Download and concatenate** (about 12 GB of PGN):
   ```sh
   cd ~/Downloads
   months=$(python3 -c "print(' '.join(f'{y}-{m:02d}' for y in range(2021,2026) for m in range(1,13) if '2021-12'<=f'{y}-{m:02d}'<='2025-11'))")
   for m in $months; do curl -O https://database.nikonoel.fr/lichess_elite_$m.zip && unzip -o lichess_elite_$m.zip; done
   for m in $months; do cat lichess_elite_$m.pgn; done > lichess_elite_2021-12_to_2025-11.pgn
   ```
2. **Build the importer:** `git checkout 18dc34f`, then do a Release build of the `DrewsChessMachine` scheme in Xcode. Do a clean build: an earlier attempt at this import silently ran a stale incremental binary.
3. **Import (no caps):**
   ```sh
   BIN=$(ls ~/Library/Developer/Xcode/DerivedData/DrewsChessMachine-*/Build/Products/Release/DrewsChessMachine.app/Contents/MacOS/DrewsChessMachine)
   "$BIN" --import-pgn ~/Downloads/lichess_elite_2021-12_to_2025-11.pgn --corpus-name lichess_elite_2021-12_to_2025-11
   ```
   Expect `imported=14619153 skipped=6429`. If you get `imported=10850514`, the binary lacks the CRLF fix.
4. **Verify:** run `python3 experiments/corpora/shard_hashes.py <new ID>` and compare `body_sha256` and the counts with the table below. Whole-file hashes never match, because the header carries the new corpus ID.
