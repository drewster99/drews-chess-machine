Core ML vs MPSGraph inference speed

inferencecoremlperformance

Question

The owner asked for a fair test of Core ML inference against our MPSGraph forward pass: same weights, same positions, each Core ML compute unit. The batch sizes that matter:

  • 1: the Lichess bot and --uci.
  • About 100, two in flight: the arena.
  • 180–250: self-play, which evaluates every game in one call per tick.

Run 1 compared MPSGraph bf16 against Core ML fp16 and summarized at batch 256 only. Run 2 adds fp16 against fp16, and the actual batch sizes.

Setup

Runs / models
Four bf16 models:
  • 20260710-1-amlg: mini, 0.24M parameters, trained.
  • 20261008-4-Ew5t: zlra shape, 3 × 128, 9×9, 8.27M.
  • 20261022-9-Hhuy: the v4_5block_7x7 preset, 8.45M.
  • 20261022-2-PswQ: 10 × 256, 3×3, 12.9M.
The last three are untrained, because timing doesn't depend on weights. Each model also has float32 and float16 copies.
Build
2607 Release (git a74e2c8f plus the benchmark code), Apple M5 Max, macOS 27.2.
Data
The 4,635 bundled test-set positions (lichess-200 + lichess-wide).
Method
--coreml-benchmark:
  • One process times from encoded boards to every output copied into the caller's buffers.
  • Every Core ML arm passes a parity check first.
  • Each cell gets an untimed warm-up, then 5 rotated rounds of 1.5 s.
  • Run 2 grid: 8 arms × batch sizes 1, 8, 32, 64, 100, 128, 180, 250, 512, 1024 × in-flight 1 and 4.
  • The fp16 pair is MPSGraph on the float16 copy against that copy's Core ML mirror export: the same ops in fp16.
  • Core ML's planned device for each op is recorded (MLComputePlan).

  • bf16 against fp16 inside MPSGraph, 8M nets: 1.05–1.27× from batch 64 up, 0.97–1.06× below.
  • Batch 1: Neural Engine 0.41–0.54 ms against MPSGraph bf16's 1.36–2.42 ms.
  • Placement: under cpu-gpu, Core ML ran the mini and 10 × 256 nets on the CPU in both runs. The fp16 exports went 95–98% to the Neural Engine on the three larger nets.
  • Parity: the fp32 exports matched exactly (100% same top move); every fp16 export 96.4–99.9%.
  • Four overlapping MPSGraph streams: +35% to +52% at batch 100, +20% to +26% at 250. At equal positions in flight the gain is 0.85–1.06× at about 250 and 1.05–1.25× at about 1,000, and real self-play runs at 9% of the GPU-only rate (OVERLAP.md, issue #23).
  • Run 1 (bf16 against Core ML, batch 256): Core ML 0.71–0.79× on the 8M nets. On shared cells, run 2's Core ML arms on the v4 preset ran 1.2–1.3× faster than in run 1; every other arm and model was within 0.94–1.06×.

Interpretation

Run 1's claims that MPSGraph is clearly faster at self-play sizes and that Core ML's fp16 is slower did not hold. Run 1 compared Core ML fp16 with MPSGraph bf16. Its 256-only summary hid that Core ML is faster below batch 64. Its gap at 256 did not repeat in run 2 (0.86–0.95× at 250), so it was within the run-to-run variation.

At equal fp16 math on the GPU, Core ML is as fast as MPSGraph or faster. MPSGraph's only advantage is bf16, worth up to 1.27× at large batches. At self-play and arena batch sizes the two cancel out on the 8M nets. Core ML also chooses its own device, and it put the 12.9M net on the CPU.

Below batch 64 Core ML is faster, and the Neural Engine wins at batch 1, but that saves only 1–2 ms per bot move.

This was one machine with "fair" thermal state in most cells. The Lichess bot played four games during run 2, at about one forward pass per 15 s. Gaps under about 1.3× may not repeat. Power was not measured.

Takeaway

Keep MPSGraph bf16 for self-play, but not because it is much faster: at the batch sizes self-play and the arena use (100–250) Core ML ties it on 8M-parameter nets (0.86–1.02×) and loses where it puts a net on the CPU (0.35–0.47× on 10 × 256). fp16 against fp16 on the GPU, Core ML is level or ahead (0.96–1.23×); MPSGraph's only edge is bf16. Core ML is faster below batch 64, and the Neural Engine at batch 1.
