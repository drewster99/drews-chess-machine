Leaky ReLU in the value head under the 1.0 ↔ 0.001 LR cycle (arm B-leaky)

lr-scheduleactivationsleaky-reluvalue-headbasic24

Question

Under the 1.0 ↔ 0.001 LR cycle, arm B (E-0017) beat constant LR by ~200 pElo, but its value head lost channels at the first LR peak: by 40k, 6 of 16 value.bn channels were past β/|γ| = −3 and 27 of 128 value-FC1 units had zero velocity; the tower and policy head had none. If the value head uses leaky ReLU, which keeps a gradient through every channel, does it stay alive, and does that change value loss or policy strength?

Setup

Net
R7's shape, basic24 input, 3 × [7×7 + 7×7] @128 pre-activation, no SE, no ReZero. ReLU everywhere except the value-head conv and value FC1 hidden layer, which use leaky ReLU (slope 0.01) (r7_basic24_leakyvalue.json, format v9). Start net 20261006-5-AUSd (--init-seed 20261005): its 61 tensors are byte-identical to B's start 20261005-22-yRzB.
Recipe
B's: parameters-B.json (cycle 1.0 ↔ 0.001, 10k period, troughs 6k / 16k / 26k / 36k, momentum 0.85 ↔ 0.95 inversely), --seed 20261005 (B's batches), corpus 20260624-192615-w3aA5b, batch 4,096, --policy-tail-precision fp32_from_pre_bn; 40,000 steps in one segment (B reached 40k by an exact resume from 36k).
Build / run
Frozen DCM-2331-4e70c615-p1headact.app (binary build 2330, sha256 1ae960792717; per-site activations phase 1). Stem 20261005-lrBleaky-cyc1, trainer ModelID 20261006-6-Xxvl, log dcm_log_20261005-204108.txt; 2026-10-05 20:41 → 2026-10-06 16:24, exit 0, final save at step 40,000. Shared the GPU throughout.
Measured
Policy probes every 1,000 steps (--probe-set wide); [LAYER-HEALTH] live lines every 50 steps and the final checkpoint block; bn_liveness.py on the step-40000 checkpoints of A, B and B-leaky.

B-leaky never had a channel past −3 in any of its 801 live layer-health lines; B had 5 dead value.bn channels by step 300 and 6 from step 1,300 on. No arm had always-on channels or non-finite values.

Interpretation

Leaky ReLU fixed what it targeted: no dead value channels and no zero-velocity FC1 units, though the value BN is still pushed negative (most negative channel −2.30, median pass-through 0.096). It changed nothing else measurable. B's dead value channels cost no value loss, and the policy probes, which do not read the value head, differ by about the low-LR probe spread; the +9.8 at 38k is inside it. The high-LR probes differ more because a mid-peak probe depends on where in an unstable stretch it lands. The ReLU tower drifts the same way in both cycled arms (block BN median β −0.45 to −0.78, blocks.2.bn1 near −2.5, blocks.1.bn1 running variance up to 95.6× its median vs A's 6.2×), so that is the cycle's effect, not the value head's; arms B-leakyall and B-silu test the tower activation. One seed per arm.

Takeaway

Leaky ReLU in the value head kept every value-head channel and FC1 unit alive (0 of 16 dead vs B's 6; 0 of 128 FC1 units at zero velocity vs 27) but left value loss and policy strength unchanged (low-LR probes −1.7 ± 9.3 pElo vs B; best 1641.7 vs 1632.0 at 38k); use it in the value head for its health, not for strength.
