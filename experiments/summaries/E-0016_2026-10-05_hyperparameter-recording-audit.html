Do saved model files record how they were trained?

provenancelineageaudit

Question

Can one .safetensors checkpoint alone say exactly how its weights were trained, across every save path, resumes, branches and live edits?

Setup

Method
Two independent read-only code audits (one blind to the other) plus header reads of every model file on disk; the fix plan was then reviewed in five passes until the second auditor concurred.
Evidence
Header census of 4,334 model files; the lineage-era files (all schema 2, all git_dirty: true), e.g. 20261004-fatconv98-cont-replay-step6093.

Interpretation

Most settings are captured for the segment that wrote a file, so recent single-segment runs are well described; multi-segment lines, branches and GUI runs are not. The plan fixes most gaps with one new lineage record format (schema 3) that older files still decode, records nothing it cannot know (absent values stay "unrecorded"), and is phased so each step builds and commits on its own. Implementation waits on owner decisions O-1 to O-18 (several involve edits to existing tests).

Takeaway

No: a lineage-era file records its own segment's 85 settings, but earlier segments, branches, GUI live edits and several settings are missing or wrong, and git_dirty is always true; a reviewed fix plan is written.
